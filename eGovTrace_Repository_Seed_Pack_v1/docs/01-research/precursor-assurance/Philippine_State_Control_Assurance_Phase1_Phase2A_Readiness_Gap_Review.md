# Philippine State Control & Assurance Universe
## Phase 1 / Phase 2A Plan — Readiness Gap Review

**Date:** August 30, 2026
**Basis:** Base document + Phase 0 Verification Log + Adversarial Challenge + Round 2 Independent Check + the proposed Phase 1/Phase 2A execution plan (FMR Reconciliation Experiment)
**Purpose:** The proposed plan is methodologically sound and is accepted at the level of strategy. This reviews it at the level of execution — what has to be resolved before it is actually runnable, not just well-reasoned.

---

## Verdict

**Accept the strategic shift. The plan is not yet execution-ready.** The gaps below are about what stops the FMR Reconciliation Experiment on day one, not about whether the direction is right.

---

## What the plan gets right (no changes needed)

- **Architecture-first → evidence-first.** Correctly follows from the base document's own instruction that Phase 2 is a feasibility test, not a build commitment (§11.6), and from Round 2's conclusion that unresolved Phase 0 items are asymmetric dependencies that shouldn't block FMR work.
- **The adversarial attack taxonomy** (identity, temporal, geographic, financial, corporate, evidence, silence attacks) is a genuine extension of the base document's "silence detection" concept (§9.4) — it operationalizes an idea the base document only named.
- **The Verification Queue (VQ-001–VQ-008)** correctly turns "someone should ask DICT" into a trackable, documented process instead of an assumed fact.
- **The stopping rule in principle** — that a negative result is itself a valid finding — is directly licensed by the base document's own closing line about acceptable outcomes.

---

## Gap 1 (the one that matters most): data access assumes a law that isn't in effect yet

The Project Reconciliation Dossier's CORPORATE and PHYSICAL sections call for SEC ownership/director data, DPWH/DA inspection reports, subcontractor identities, and completion evidence. But the base document's own §2.2 and §4.2 findings are that the RTI/FOI Act remains pending bicameral reconciliation, and that "no amount of software substitutes for the missing statute."

This creates a direct tension the plan doesn't resolve:
- As an independent researcher, standing to request internal DA/DPWH inspection reports is not established — these may not be proactively public at all pre-RTI.
- SEC ownership data beyond the basic General Information Sheet (directors, officers, listed stockholders) typically requires a paid request through SEC's own channels (e.g., its Express/iView systems) and does not straightforwardly yield full beneficial-ownership chains.
- FMR Watch and PhilGEPS Open Data are genuinely public and usable now; internal audit/inspection material is not confirmed to be.

**What's needed before Phase 2A starts:** a per-data-category access map — for each field in the dossier template, mark it (a) pullable now from a public portal, (b) requestable via a formal but non-RTI channel (e.g., paid SEC request), or (c) blocked until RTI/FOI passes or a partner institution provides access. Categories in (c) should be explicitly logged as "unresolved by design," not silently attempted.

---

## Gap 2: no pre-registered stopping-rule thresholds

"Kill or narrow if the problem isn't sufficiently systemic, reproducible, or automatable" is the right instinct, but nothing defines "sufficiently" in advance. Without a threshold set before the trace begins, the eventual verdict risks being read backward from whatever result actually comes out — exactly the kind of motivated reasoning the base document's evidence discipline (CONFIRMED/PARTIAL/UNCERTAIN) is designed to prevent elsewhere.

**What's needed:** concrete pass/fail criteria fixed before the trace starts — for example, a minimum number of system-pairs that must be manually matchable within a defined time budget, plus at least one genuine cross-system contradiction found, as the bar for "worth pursuing further."

---

## Gap 3: no named candidate projects

The base document's own candidate — the Lower Binogsacan, Guinobatan ghost project, paired with a completed FMR project — is not selected here, and no screening criteria are proposed for picking a completed counterpart with enough public data to actually populate the dossier. The plan is a template without subjects.

**What's needed:** a short screening pass against FMR Watch's public records to confirm the Guinobatan project (or an alternative) has enough public-source coverage across PIPOL/UACS/PhilGEPS/PSGC to be worth tracing before committing dossier-building effort to it.

---

## Gap 4: publication and personal exposure risk is not addressed

The dossier will eventually name specific contractors, officials, and discrepancies, produced by a solo, independently-operating researcher without institutional backing. Philippine libel law is strict, and the base document's "connection is not corruption" principle (§7.2) is framed as an architectural safeguard — it has no equivalent yet for how findings get worded, reviewed, or shared publicly.

**What's needed:** a stated rule for how findings will be published — at minimum, that any output naming a specific person or firm distinguishes documented fact from inference, consistent with the base document's own Fact → Claim → Evidence → Inference chain (§7.2), before anything is shared outside the research process itself.

---

## Gap 5: Phase 1 and Phase 2A aren't wired together

Phase 1 (the institution → mandate → system → asset schema) and Phase 2A (the FMR dossier) are presented as parallel tracks. Nothing specifies whether the FMR-relevant institutions (DA, BAFE, DPWH, DBM, PSA, PS-DBM/GPPB) need to be populated in the Phase 1 schema before the dossier work starts, or whether they're genuinely independent.

**What's needed:** a one-line sequencing decision — most naturally, populate the Phase 1 schema only for the institutions the FMR trace actually touches, so Phase 1 produces the join keys Phase 2A needs rather than running as unrelated ecosystem mapping.

---

## Gap 6: scope realism for solo execution

Seven dossier sections, times two projects, times seven attack types, plus a scorecard, is substantial manual effort for one person alongside an 8-item verification queue. The plan doesn't sequence its own workload.

**What's needed:** attempt identity, temporal, and geographic consistency first (the fields most likely to be publicly resolvable), and treat corporate and evidence-attack layers as a second pass — so a partial result is available even if the full dossier isn't completed for both projects.

---

## Net effect

None of these gaps contradict the plan's direction — they are what "ready to go" still requires. The strategic pivot (evidence-first experimentation over continued architecture mapping) stands. Before Phase 2A actually starts: map data access per field, fix the pass/fail thresholds, pick the two real projects, decide the publication-safety rule, and sequence Phase 1 to serve Phase 2A rather than run alongside it.
