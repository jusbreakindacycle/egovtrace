# 13. False-Join Testing — Built Into Case A

False-join testing was executed as part of the case rather than deferred.

## 13.2 Same location / route

**Disposition:** records remain separate.

## 13.3 Same contractor

A-Cube Construction and Supply is documented for the selected 2021 project in agency-origin secondary evidence. Contractor identity alone is not accepted as a bridge to another project or procurement record.

**Disposition:** corroborative only unless joined with additional evidence.

## 13.4 Same amount

₱12.5M is not treated as a unique identity key because many government infrastructure projects use the same nominal amount.

**Disposition:** J5 if used alone.

## 13.5 Same UACS / code family

The case contains an explicit historical identifier-variation problem: FY2021 NEP and direct-release representations use different UACS codes for the same project.

**Disposition:** variation is recorded; no automatic contradiction is declared.

## 13.6 Temporal collision test

Older and newer Cabarasan–Dao records are not merged with the selected 2021 project merely because the route name overlaps.

**Disposition:** separate temporal interventions pending additional physical/project evidence.

# 18. What This Case Demonstrates for eGovTrace

Case A provides a concrete demonstration of the architecture's central claim:

```text
Government records exist
        ↓
Project identity is recoverable
        ↓
Budget identity is recoverable
        ↓
Implementation evidence is recoverable
        ↓
But cross-system procurement identity is not automatically exposed
        ↓
Therefore downstream financial continuity becomes difficult to prove
```

The bottleneck is therefore not simply “missing payment information.”

It is the absence of a defensible bridge identifier at an earlier transition.

This is exactly the type of evidence-gap state that eGovTrace is intended to model.
