# T007.3 — Reconciliation Application Service Implementation Task

**Status:** Proposed implementation task  
**Task:** T007.3 implementation  
**Depends on:** T007.3 Reconciliation Application Service Specification; T007.3 Implementation Specification; T007.1 deterministic reconciliation matcher; T007.2 reconciliation persistence  

## Objective

Implement the smallest application-layer service that orchestrates exact control-path resolution, observation acquisition, T007.1 reconciliation, T007.2 persistence, finalization, and deterministic queries.

The application service is an orchestration boundary. It must not introduce new domain semantics.

## Required implementation

Create an application package following the existing monorepo conventions, with the smallest necessary boundary:

```text
packages/application/src/reconciliation/
  contracts.ts
  errors.ts
  ports.ts
  service.ts
  index.ts
```

Required capabilities:

1. Execute reconciliation.
2. Finalize reconciliation.
3. Get persisted reconciliation.
4. List reconciliations by control-path identity and optional version.

## Required ports

The service must depend on explicit abstractions for:

- exact `ExpectedControlPath` retrieval;
- observation retrieval;
- T007.2 persistence repository operations.

No direct SQL from the application layer.

## Execute behavior

The service must:

1. Validate command shape before repository writes.
2. Resolve the exact requested control-path ID and version.
3. Reject missing or version-inconsistent control paths.
4. Use explicitly supplied events when present, including an empty array.
5. Invoke the observation provider only when events were not supplied.
6. Distinguish `AVAILABLE + []` from `UNAVAILABLE`.
7. Never translate unavailable observations into `NOT_OBSERVED`.
8. Build the exact `ReconciliationRun` required by T007.1.
9. Invoke `reconcile()` exactly once for a non-replayed execution.
10. Pass the complete result unchanged to the T007.2 repository.
11. Propagate the caller idempotency key unchanged.
12. Return the persisted representation.

## Finalization behavior

Finalization must be thin and must not recalculate reconciliation.

It must validate the run ID and expected record version, delegate to the repository, and translate concurrency or immutability failures into stable application errors.

## Query behavior

Queries must be read-only, must not reconstruct missing data, and must preserve repository ordering.

## Error behavior

Implement stable application error categories covering at minimum:

- invalid command;
- control path not found;
- invalid control-path version;
- observation unavailable;
- reconciliation not found;
- idempotency conflict;
- concurrency conflict;
- reconciliation immutable;
- domain validation failure;
- persistence failure;
- invalid authorization context.

Do not expose secrets or internal credentials through error messages.

## Critical invariants

The implementation must preserve:

- connection is not corruption;
- not observed is not absent;
- unavailable is not false;
- identifier recovery is not proof;
- payment instruction is not payment settlement;
- applicability remains explicit;
- multiple candidates remain multiple candidates;
- historical control-path versions remain immutable;
- persistence is semantically lossless;
- AI cannot alter reconciliation decisions.

## Explicitly forbidden

Do not add:

- matching criteria;
- entity resolution;
- identifier recovery;
- connector-specific heuristics;
- anomaly detection;
- risk scoring;
- evidence credibility assessment;
- accountability decisions;
- legal findings;
- corruption classification;
- AI adjudication;
- UI or transport adapters;
- source-record mutation;
- unrelated repository refactors.

## Testing requirements

Add unit/service tests for:

- valid execute flow;
- exact control-path version resolution;
- missing control path;
- invalid command input;
- supplied events including an empty array;
- provider availability and unavailability;
- provider failure propagation;
- applicability preservation;
- T007.1 result preservation;
- T007.2 persistence delegation;
- idempotency-key propagation;
- finalization delegation;
- concurrency and immutable errors;
- get/list behavior;
- deterministic ordering preservation;
- authorization-context validation;
- no direct application-layer SQL;
- no AI influence on outputs.

Adversarial tests must explicitly challenge the distinctions between empty observations and unavailable observations, multiple matches and single selections, and historical path versions and latest-version substitution.

## Acceptance criteria

T007.3 implementation is accepted only when:

- the application package exists at the smallest justified boundary;
- the service delegates domain matching to T007.1;
- the service delegates persistence to T007.2;
- no reconciliation semantics are duplicated in the service;
- all required error mappings are covered by tests;
- unavailable observations cannot become `NOT_OBSERVED`;
- supplied empty observations do not trigger provider lookup;
- exact control-path versions are preserved;
- finalization does not recalculate;
- queries do not reinterpret results;
- the repository's existing CI checks remain green.
