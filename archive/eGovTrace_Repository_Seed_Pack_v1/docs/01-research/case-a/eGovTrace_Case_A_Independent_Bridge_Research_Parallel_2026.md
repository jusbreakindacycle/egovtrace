- the research rule requires explicit continuity evidence before merging temporal project representations.

This is a useful example of why a future eGovTrace system must model temporal project succession rather than deduplicate on title alone.

## 10. PhilGEPS structural observation

Current PhilGEPS documentation/public interfaces demonstrate that bid notices have a system-generated Reference Number, while procuring entities may also use a Solicitation Number. Award and contract information are represented separately in procurement records.

This supports the study's identifier taxonomy:

```text
PROCUREMENT REFERENCE
≠
SOLICITATION NUMBER
≠
AWARD NOTICE NUMBER
≠
CONTRACT NUMBER
≠
PROJECT ID
```

A future bridge cannot therefore assume one procurement-side number is automatically the universal project key.

Source: current PhilGEPS public Bid Notice Abstract structure and Open PhilGEPS public reporting interface.

## 13. New result from parallel research

The strongest new research result is not a recovered procurement identifier.

It is a more precise **temporal identity boundary**:

```text
2016 Cabarasan–Dao intervention
        ≠
2021 selected Cabarasan–Dao intervention
        ≠
later/current Cabarasan–Dao representations
```

unless future evidence establishes a documented successor, extension, rehabilitation, or project-component continuity.

This is an important validation result for eGovTrace because it demonstrates the need for:

```text
TEMPORAL PROJECT LINEAGE
+
PROJECT SUCCESSION RELATIONS
+
EXPLICIT JOIN BASIS
```

rather than title-based deduplication.

## 14. Impact on the central research question

The parallel public-source branch does not yet close the financial bridge.

It does strengthen three findings:

1. **Project-to-budget continuity is independently reproducible.**
2. **Implementation/contractor evidence exists at agency-origin secondary level.**
3. **Historical/successor-looking records create genuine false-join risk.**

```text
PROJECT
  ↓
PRIMARY PROCUREMENT
```

not:

```text

  ↓
PAYMENT
```

because the intermediate procurement/contract identity has not yet been defensibly established.
