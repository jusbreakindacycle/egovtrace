# G1.3c — Financial Authority & Transaction-Key Discovery

**Program:** eGovTrace / Philippine State Control & Assurance Research  
**Research Track:** FMR Reconciliation Experiment  
**Gate:** G1.3c  
**Status:** FROZEN  
**Disposition:** PARTIAL PASS

## 1. Purpose

Determine whether the unresolved financial joins can be recovered through native authority and transaction identifiers rather than by forcing aggregate public reports to function as project-level ledgers.

The test examined:

- SARO
- NCA
- DMS references
- allotment / sub-allotment / Sub-ARO
- FAR No. 1B structures
- ORS
- contract references
- Disbursement Voucher (DV)
- LDDAP-ADA / ADA
- JEV
- BTMS
- IFMIS-linked architecture
- document-authenticity mechanisms such as ADRS

## 2. Core finding

Native identifiers exist between budget, authority, obligation, payment, and accounting layers.

A representative reconciliation architecture is:

```text
Budget / PAP
    ↓
DMS Reference
    ↓
SARO / NCA
    ↓
Allotment / Sub-ARO
    ↓
ORS
    ↓
DV
    ↓
LDDAP-ADA / ADA
    ↓
Payment
    ↓
JEV
```

This is a graph of possible institutional relationships, not a claim that every transaction must follow every step.

## 3. SARO

### Finding

SARO is a real financial authority instrument with its own native authority number and associated fields such as release date, agency, operating unit, amount, and purpose.

### New Casay result

No confidently project-specific New Casay SARO was recovered.

### Disposition

**Authority mechanism: CONFIRMED**  
**New Casay join: UNRESOLVED**

## 4. NCA

### Finding

NCA is a distinct cash authority with native numbering and agency / operating-unit context.

### Limitation

NCA is not automatically equivalent to payment for one project. It may support broader organizational or program-level purposes.

### New Casay result

No confidently project-specific NCA was recovered.

### Disposition

**Authority mechanism: CONFIRMED**  
**Project-specific join: UNRESOLVED**

## 5. DMS Reference

DBM process documentation establishes a DMS Reference Number within the processing of funding authorities.

This makes it a potentially valuable upstream bridge into SARO/NCA processing.

No New Casay-specific DMS reference was recovered.

**Disposition: identifier class CONFIRMED; New Casay recovery NOT ACHIEVED.**

## 6. Sub-ARO / Sub-Allotment

DBM recognizes sub-allotment and Sub-ARO as financial-control objects, and FAR No. 1B provides a reporting structure for allotments and sub-allotments.

This layer is especially important because it may bridge central funding authority to the implementing operating unit.

No New Casay-specific Sub-ARO was recovered.

**Disposition: concept CONFIRMED; potential bridge value HIGH; project-level recovery NOT ACHIEVED.**

## 7. ORS

ORS is a strong obligation-side transaction key.

Official transaction documentation demonstrates a real-world chain in which an ORS is associated with a subsequent Disbursement Voucher and payment instrument.

This establishes that obligation-to-payment reconciliation can, in principle, proceed through native transaction identifiers rather than a single project code.

No New Casay-specific ORS was recovered.

**Disposition: transaction identifier CONFIRMED; bridge value HIGH; project-specific join NOT ACHIEVED.**

## 8. Disbursement Voucher

DV is a strong payment-side transaction key and can be related to ORS and subsequent payment instruments.

No New Casay-specific DV was recovered.

**Disposition: transaction identifier CONFIRMED; payment-side bridge value HIGH; project-specific join NOT ACHIEVED.**

## 9. LDDAP-ADA / ADA

These payment-side references can provide downstream evidence of payment execution after the DV stage.

The existence of a payment reference must not automatically be interpreted as proof of project attribution without the upstream relationship.

**Disposition: identifier class CONFIRMED; New Casay-specific recovery NOT ACHIEVED.**

## 10. JEV

JEV provides accounting-side corroboration and can validate that a transaction reached accounting records.

For the initial project-to-money experiment, ORS → DV → payment references are the preferred operational chain. JEV is best treated as corroborating evidence.

**Disposition: CONFIRMED; corroborating value MEDIUM/HIGH.**

## 11. Contract references

Contract identifiers are high-value bridge candidates between procurement and financial execution:

```text
Procurement ID
   ↓
Contract No.
   ↓
Contract value / funding context
   ↓
ORS
```

The earlier procurement experiment demonstrated why this must be identity-controlled: a real contract can exist and still be the wrong contract for the target FMR.

No complete New Casay contract-to-ORS chain was established.

**Disposition: bridge hypothesis HIGH; New Casay join UNRESOLVED.**

## 12. BTMS / IFMIS

BTMS exists as a modernization architecture intended to support accounting, obligation monitoring, and disbursement monitoring. However, nationwide integration is still an evolving rollout rather than evidence of one completed public transaction database.

Therefore:

```text
BTMS exists ≠ universal public transaction access
```

No New Casay BTMS transaction-level join was established.

**Disposition: system existence CONFIRMED; public project-level join NOT ESTABLISHED.**

## 13. ADRS and document integrity

DBM's document-verification capability for key budget-release documents addresses authenticity and integrity.

It does not by itself establish semantic identity between a financial authority and a real-world FMR.

Therefore:

```text
Document integrity ≠ semantic reconciliation
```

## 14. Frozen architecture

The research rejects the assumption of a single universal financial identifier.

Instead, eGovTrace should preserve each institutional representation and the relationship between representations.

### Financial Representation

At minimum:

- native identifier
- identifier type
- issuing institution
- issuing system
- operating unit
- representation type
- effective period
- source record
- access basis

### Representation Relationship

At minimum:

- source representation
- target representation
- relation type
- evidence
- source document
- temporal validity
- verification / confidence status

## 15. Relationship status model

Use explicit states:

- **CONFIRMED JOIN** — directly evidenced
- **PROBABLE JOIN** — strongly supported but lacking a direct authoritative key
- **POSSIBLE JOIN** — plausible but insufficiently evidenced
- **UNRESOLVED JOIN** — neither established nor rejected
- **REJECTED JOIN** — evidence shows the representations are not the same

An unresolved join must never become an accusation.

## 17. Final conclusion

The missing financial join is not necessarily a missing government record.

It may be a missing **publicly recoverable chain of identifiers across institutional representations**.

The appropriate eGovTrace role is therefore:

```text
preserve native identifiers
        ↓
map representation relationships
        ↓
preserve time and source provenance
        ↓
classify join status
        ↓
flag unresolved gaps
```

not:

```text
unresolved join
        ↓
missing money
```

## 18. Frozen disposition

**G1.3c: PARTIAL PASS**

The financial authority and transaction-key architecture is confirmed as a real research path. A complete New Casay project-to-payment reconstruction was not achieved from the public evidence available in this gate.

### Remaining highest-value bridge targets

1. Contract reference / Notice of Award / Contract Number
2. Funding-source / PAP reference
3. Sub-ARO or sub-allotment reference
4. ORS
5. Disbursement Voucher
6. LDDAP-ADA / ADA or equivalent payment reference

Any future retrieval must preserve the distinction between **not observed**, **unavailable**, **unresolved**, and **rejected**.
